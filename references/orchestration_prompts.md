# 超长档编排任务卡（仅 >60 页技术报告/综述/学位论文，或用户点名编排时使用）

> **启用条件**：Phase 0 判定为超长档（内部值仍记 `deep`，兼容存量条目）。普通论文**不要**用本文件——single-pass 主会话通读 + 统一 QA（SKILL Phase 2/3.4）更快更省，效果等价。
> **成本预期**：3 组并行 ≈ 全文 2-3× token；仍高于 standard 档（~1.2-1.8×），这是换"后段维度不失焦"的钱，只在超长文本上划算。
> **单一来源原则**：各维度的分析要求以 `SKILL.md` Phase 2 原文为准——派发时主会话把对应维度原文**整段粘贴**进任务卡【分析要求】槽位；本文件只提供骨架、契约与 QA 卡，避免双处维护规则漂移。

---

## 派发前必做（五条，全部源于真实故障）

1. **绝对路径纪律**：任务卡中一切路径必须展开为**完整绝对路径**，禁止 `...` 简写——子代理工作目录不可假设（实测简写导致整组阻塞 10 分钟）。
2. **视觉分工**：子代理会话**无视觉通道**（Read PNG 返回 `[Unsupported Image]`，vision API 亦被阻断）——主会话在派发前**亲自 Read 将被报告引用的关键图**，把观察文本以"【主会话视觉观察记录】…"注入对应任务卡；子代理一律不得试读 PNG 或调 vision API，图相关结论只引用注入的观察并标 `[据主会话视觉核验]`，无记录可引则标"未经视觉核验"。
3. **外部断言补验**：子代理会话**无 MCP 工具**——外部断言一律标 `【待核验】`；主会话装配前用 CLI 批量补验并落台账：
   ```bash
   python -c "import sys; sys.path.insert(0,'<skill_dir>'); from mcp_server import cite_api; ..."
   ```
   结果写 `<vault_dir>/cite_ledger.json`（verdict/year/venue/cites/author_match），装配时按台账补 `[外部核验: …]` 标注。
4. **页码契约**：锚点页码一律指 **PDF 物理页序 = `.pdf_page_i.txt` 文件编号**；印刷页标常有 −1/−2 漂移（实测三卡对同一表报 p.15~p.17，真值 p.18），装配"六对张力"第 6 项以文件为准。
5. **分页硬契约（防重复读，编排成本失控的头号原因）**：主会话先做一遍**结构预扫描**（章节→页码映射 + 图表清单），据此给每组任务卡列**死读页清单**（如 `p1-3,10-14`），并写明"清单外禁读、组间并集须覆盖全页"——五组各读全书的 2026-09-25 首跑模式（全文被读 3-5 遍）予以废除。

**通用纪律（写进每张任务卡"硬性纪律"段）**：锚点必附 / 三态标注 / 外部断言【待核验】/ 不编造 / 互不读卡 / 只写自己卡 / **卡片 ≤120 行**——卡片只存结论与锚点，长文叙述属于报告，**禁止双写**。

**维度卡固定格式**：

```markdown
# 维度卡 · [组名]（→报告 §X.Y-§A.B）
## 结论清单
- [C1] 结论一句话 | 锚点: p.X §Y | 标注: 明述/推断/重构 | 置信: 高/中/低
## 数字台账
| 数字/引用 | 值 | 锚点 |
## 待核验/存疑
```

## 三张并行任务卡（同一条消息内并行派发，subagent_type: general-purpose）

**任务卡 A · 脉络与方法** → 报告 §1.1-1.4、§2.1-2.8、基础知识地图、核心图速览图 A 块
- 【分析要求】←粘贴 SKILL 维度 2.1 + 2.3 全文（含思维链证据规则、图文结合、双层讲解）
- 【读页清单】←预扫描给出：引言/相关工作/结论页 + 方法章节全部页
- 【注入】关键架构图的【主会话视觉观察记录】

**任务卡 B · 实证与审稿** → 报告 §3.1-3.6、§4.1-4.7（含 §4.3 沉默对照清单初稿）
- 【分析要求】←粘贴 SKILL 维度 2.4 + 2.5 + 2.6/2.7/2.8 全文（含数据集卡样本三态、基线深析、资源估算工具箱）
- 【读页清单】←实验章 + 附录表格页 + 案例研究页；结果曲线图的【主会话视觉观察记录】注入
- 【特别任务】资源账本：论文交代值 + 未交代项用估算工具箱给区间

**任务卡 C · 深析** → 报告 §4.8-4.9
- 【分析要求】←粘贴 SKILL 维度 2.9/2.10 全文
- 【读页清单】←公式定义页 + 消融表页 + 数据集描述页（最小集合，通常 ≤12 页）

## 装配与矛盾检测（主会话，Phase 3）

三卡回收 → 通读 → 按模板装配成报告（过渡与合并是主会话的写作，卡片只是骨架）。装配时逐项核对**六对张力**，分歧三选一：派仲裁卡 / 写入"⚠️ 矛盾与仲裁记录" / 确认某卡有误（修正留痕）。**禁止静默择一。**

| # | 交叉对 | 检查什么 |
|---|--------|---------|
| 1 | A×B | 动机叙述 vs 审稿判定是否互相拆台 |
| 2 | A×B | "设计 X 为了 Y" vs 消融数字（去掉 X 影响≈0 则矛盾） |
| 3 | A×B | 同一 Figure 的读数是否同图异说 |
| 4 | A×B | 两卡各自列的"前人/同期工作"清单口径是否一致 |
| 5 | C×B | 隐含假设 vs 数据集卡（如"无泄漏"假设 vs 饱和基准） |
| 6 | 全部 | 锚点抽查：随机 8-10 条回 .pdf_page_i.txt 验证（页码契约见必做第 4 条） |

**仲裁卡**（需要裁决时派单个子代理）：

```
你是仲裁员。矛盾：[两卡原文各引，附锚点]。只读：涉事页码±1 与涉事图（引用下方观察记录）。
产出：谁对/都对(口径不同)/原文自相矛盾(写入⚠️节)/两卡皆误(修正+锚点)。禁止泛读全文。
```

## 统一 QA 卡（装配完成后派发一次，standard / 超长档通用）

```
你是独立验收审计员（全新上下文，不参与写作）。输入：装配完的报告 + PAGE_DIR（按需抽查才读）。
一趟完成两类检查，输出 REWORK 清单（每条含定位与整改要求）或 PASS：
[事实面] 1. 数字/锚点抽查 15 处（回原文核值与语义）；2. 三态标注覆盖：§1.4 思维链、
数据集样本、资源估算三处逐条查；3. 外部断言核验覆盖率（对照 cite_ledger.json 或报告内
【待核验】残留数）；4. 图解读是否引用图内可见元素（对照注入的视觉观察/文本层佐证）。
[可读面] 5. 扮演陌生研究生只读报告答五问（问题/机制复述/关键数字含义/最大局限/值不值）；
6. 随机抽 6 个首现术语查当场解释。
输出格式：FACT-REWORK[] / READ-REWORK[] / VERDICT=PASS|REWORK(n)。
```

**返工规则**：主会话修复后**只复审失败项一次**；仍有未决 → 写入报告"✅ 验收记录"如实收口。QA 的价值是"外来者的眼睛"——一趟合并检查即可，不得回退成多代理多轮循环。

---

## 成本与时序说明

- 三组并行 + 分页硬契约下，编排总读量 ≈ 全文 1.1-1.3 遍 + 装配复读卡片，显著低于首跑（3-5 遍）
- `.dimcards/` 验收通过后保留（供 Phase 5 复用），不删除
- 若用户只是"想读得细"而论文 ≤60 页：留在 standard 档，建议其读完后用 `paper_get` 回查，而非升档烧钱
