# Deep 档编排任务卡（Phase 2 deep 分支 / Phase 3 装配与双 QA 使用）

> **何时读本文件**：仅当 Phase 0 分诊结果为 `deep`（或用户指定深读）时。standard 档不需要本文件。
> **单一来源原则**：各维度的分析要求以 `SKILL.md` Phase 2 原文为准——主会话派发任务时把对应维度原文**整段粘贴**进任务卡的【分析要求】槽位，本文件只提供任务卡骨架、输入契约与产出格式，避免两处维护规则导致漂移。

---

## 通用输入契约（每个子代理都给定）

| 变量 | 值 |
|------|----|
| `PAGE_DIR` | `<vault_dir>/.extract_tmp/`（逐页文本 `.pdf_page_i.txt`，i=1..N） |
| `FIG_DIR` | `<vault_dir>/attachments/<short_name>/`（裁图 + `manifest.json`） |
| `REPORT_SPEC` | `references/report_template.md`（只读目标小节结构） |
| `OUT_DIR` | `<vault_dir>/reports/.dimcards/<short_name>/`（维度卡输出目录，主会话建） |

## 派发前必做（2026-09-25 实战修订，四条纪律全部源于真实故障）

1. **绝对路径纪律**：任务卡中一切路径必须展开为**完整绝对路径**，禁止 `...` 简写或相对引用——子代理工作目录不可假设，实证一次简写导致整组阻塞 10 分钟。
2. **视觉分工**：子代理会话**无视觉通道**（Read PNG 返回 `[Unsupported Image]`，vision API 通道亦被 harness 阻断）——因此：主会话在派发前**亲自 Read 将被报告引用的关键图**，把观察文本以"【主会话视觉观察记录】…"段落注入对应任务卡；子代理一律不得尝试读图或调 vision API，图相关内容引用注入的观察文本并标注 `[据主会话视觉核验]`。
3. **外部断言补验**：子代理会话**无 MCP 工具**——`cite_verify`/`paper_citations` 不可调用。任务卡纪律改为：外部断言一律标 `【待核验】`；主会话在装配前用 CLI 批量补验：
   ```bash
   python -c "import sys; sys.path.insert(0,'<skill_dir>'); from mcp_server import cite_api; ..."
   ```
   结果写 `<vault_dir>/cite_ledger.json`（含每条 verdict/year/venue/cites/author_match），装配时按台账为报告补 `[外部核验: …]` 标注。
4. **页码契约**：所有锚点页码一律指 **PDF 物理页序 = `.pdf_page_i.txt` 文件编号**。论文印刷页标/附录编号与物理页常有 −1/−2 漂移（实测：三张卡对同一 Table 报 p.15~p.17，真值 p.18），装配"六对张力"第 6 项的锚点抽查以文件为准。

**通用纪律（写进每张任务卡的"硬性纪律"段，不可省略）**：
1. 每条结论必须附**原文锚点**（`p.X §Y` / `Table Z` / `Eq.(n)` / `Figure W`），无锚点的结论一律降级为"待核验"
2. 解读其他论文 / 外部事实断言：子代理无 MCP，一律标 `【待核验】`，由主会话装配前按"派发前必做"第 3 条 CLI 批量补验
3. 推断性内容用三态标注：`[原文 §X 明述]` / `[据 X 推断]` / `[重构——原文未交代]`
4. 禁止编造样本、数字、图内容；给不出证据就明写"未找到"
5. **不读其他组的维度卡**（独立上下文正是矛盾检测的前提）
6. 只写自己的维度卡文件，不修改任何共享文件
7. **不尝试读 PNG 或调 vision API**（视觉通道在子代理不可用）——图相关结论只引用任务卡内"主会话视觉观察记录"，无记录可引时标"未经视觉核验"

**维度卡固定格式**：

```markdown
# 维度卡 · [组名]（对应报告 §X.Y-§A.B）
## 结论清单
- [C1] 结论一句话 | 锚点: p.X §Y | 标注: 明述/推断/重构 | 置信: 高/中/低
- [C2] ...
## 引用与数字台账
| 数字/引用 | 值 | 锚点 | 已抽查? |
## 待核验/存疑
- [Q1] 需要仲裁或主会话补验的事项
## 产出文件
- 嵌入图（B/C 组）: 列文件名与对应 Figure 编号
```

## 五张并行任务卡（主会话在同一消息内并行派发，subagent_type: general-purpose）

**任务卡 A · 脉络组** → 报告 §1.1-1.4
- 读取范围：`.pdf_page_1.txt` 起前 3 页（引言）+ 结尾 2 页（结论/讨论）+ 相关工作章节页
- 【分析要求】←粘贴 SKILL 维度 2.1 全文（含思维链证据规则）+ 报告 §1.3"作者如何发现"要求

**任务卡 B · 方法组** → 报告 §2.1-2.2, §2.4-2.8 + 核心图速览"图 A"块
- 读取范围：方法章节全部页；架构/pipeline 图**引用任务卡内【主会话视觉观察记录】**（子代理不读图，见"视觉分工"）
- 【分析要求】←粘贴 SKILL 维度 2.3 全文（含图文结合硬性、双层讲解）

**任务卡 C · 实证组** → 报告 §3.1-3.6 + 数据集卡 + 基线深析 + §2.7 资源账本
- 读取范围：实验章节 + 附录表格页；结果曲线/定性图引用注入的【主会话视觉观察记录】，无记录可引的图结论标"未经视觉核验"
- 【分析要求】←粘贴 SKILL 维度 2.4 全文（含数据集深析三选一样本规则、基线公平性、资源估算工具箱）

**任务卡 D · 审稿组** → 报告 §4.1-4.7（含 §4.3 沉默对照清单初稿）
- 读取范围：全文（重点：摘要声称、实验表、附录消融）
- 【分析要求】←粘贴 SKILL 维度 2.5/2.6/2.7/2.8 四段全文

**任务卡 E · 深析组** → 报告 §4.8-4.9
- 读取范围：方法公式 + 消融表 + 数据集描述页
- 【分析要求】←粘贴 SKILL 维度 2.9/2.10 全文；外部替代方案断言标 `【待核验】`（主会话按台账补验）

## 装配与矛盾检测（主会话，Phase 3）

维度卡全部回收后，主会话通读五卡 → 按报告模板装配。**装配时逐项核对以下六对张力**（发现矛盾写入"⚠️ 矛盾与仲裁记录"节，不静默择一）：

| # | 交叉对 | 检查什么 |
|---|--------|---------|
| 1 | A × D | A 的问题动机叙述 vs D 的新颖性/拒稿判定，是否互相拆台 |
| 2 | B × C | B 声称"设计 X 为了 Y" vs C 的消融数字——X 去掉影响≈0 则矛盾 |
| 3 | B × C | B 读图结论的 Figure 编号 vs C 台账的图号/数字，是否同图异说 |
| 4 | A × D | 两组各自列出的"前人/同期工作"清单，重复条目口径是否一致 |
| 5 | E × C | E 的隐含假设 vs C 的数据集卡（如"数据无泄漏"假设 vs C 发现饱和基准） |
| 6 | 全部 | 各卡锚点抽查：随机 8-10 条，回 PAGE_DIR 对应页确认存在且相符 |

**仲裁卡**（任一矛盾需要裁决时派发，单个子代理）：

```
你是仲裁员。矛盾：[引用两卡原文，各附锚点]。
只读：PAGE_DIR 第 [涉事页码±1] 页、FIG_DIR [涉事图]。
产出：谁对/都对(口径不同)/都对(原文确实自相矛盾——写入报告⚠️节)/两卡皆误(给修正结论+锚点)。禁止泛读全文。
```

## QA-1 任务卡 · 事实审计员（deep 必跑；standard 可选）

```
你是独立事实审计员，不参与写作。输入：装配完的报告全文 + PAGE_DIR + FIG_DIR/manifest.json。
抽查清单（每项给 通过/返工+位置）：
1. 数字抽查 ≥15 处：报告数字逐个回 PAGE_DIR 找原文；换算/衍生是否标注
2. 每张嵌图：解读是否引用了图内可见元素（轴名/图例/曲线走向），还是纯正文转述
3. 三态标注覆盖率：§1.4 思维链、数据集样本、资源估算三处逐条查
4. cite_verify 覆盖率：报告中带 [外部核验] 的条目数 vs 关于其他论文的断言总数
5. 锚点抽验 10 条（与装配第 6 项错开取样）
6. §4.3 沉默清单、⚠️矛盾记录的引用是否真实存在于对应小节
输出：PASS 清单 + REWORK 清单（每条含报告行号级定位与整改要求）。
```

## QA-2 任务卡 · 可理解性审计员（deep 必跑）

```
你扮演不熟悉该子领域的一年级研究生，只允许读这份报告本身（禁止读原文/其他材料）。
依次回答五问（每题：答得出/答不出+卡在第几节）：
① 这篇论文要解决什么问题，为什么值得做？
② 方法的核心机制是什么？输入到输出怎么走？
③ 最重要的一个实验数字是多少，意味着什么？
④ 方法最大的局限是什么？
⑤ 一句话总结这篇论文值不值得深入。
另：随机挑 6 个首次出现的专业术语/缩写，检查是否当场有解释，列违规位置。
答不出的每一处 = ELI5 失败点，输出 REWORK 清单（定位到节）。
```

**返工规则**：REWORK 项由主会话修改报告 → 只复审该 QA 项（重派对应审计员）；同一项最多 2 轮；仍有未决项 → 如实写入报告"✅ 验收记录"的未决清单（禁止静默放行）。

## 成本与时序说明

- 五组并行派发（同一条消息内多个 Agent 调用），维度卡数分钟回收；总 token ≈ 单上下文的 3-6×，换来每组满血上下文与独立视角
- 短论文（body ≤12 页）不要走 deep——分诊表已限制；用户坚持深读时提醒成本后可放行
- `.dimcards/` 目录在验收通过后保留（供 Phase 5 对比引用），不删除
