# 文献解读报告模板

以下模板用于生成每篇论文的中文解读报告。严格遵循此结构，但各节的细分小节可根据论文特点灵活调整。

> **排版原则**：多使用表格、代码框、分隔线、图标标记来打破纯文字块，避免大面积连续 `>` 引用块。关键数据用**粗体**或表格突出，核心洞察用 `> 💡` 标注，重要警告用 `> ⚠️` 标注。

---

## ⚠️ 零基础可理解性原则（最高硬性要求）

> **本报告的每一位读者，**无论其专业背景如何**，读完报告后都必须能理解论文的核心思想、方法和结论。**

**这条原则的具体要求**：

1. **每个概念首次出现时必须解释**
   - 论文术语（如"晚期交互 late interaction"、"特征融合 feature fusion"）
   - 论文引用但未解释的方法/模型（首次提到时附"一句话定位"）
   - 缩写（MLLM、KB-VQA、RAG、CLIP 等）

2. **每个变量/符号首次出现时必须定义**
   - 数学符号（$k$、$d$、$\bar{d}$、$L$、$B$ 等）
   - 张量形状（`[B, L, D]` 每个维度的含义）
   - 论文自定义的变量（即使 $E_l^T$、$h_l$ 也要解释）

3. **每个数字/指标首次出现时必须说清"是什么、为什么高/低"**
   - 评估指标（R@5、PR@5、nDCG 等）
   - 性能对比的"相对提升"含义
   - 训练资源（"80 GPU 小时" → 给出"1 块 A100 跑 3.3 天"这种直观对比）

4. **每个引用前人工作时必须"一句话定位"**
   - ❌ 错误：`如 [FLMR] 所示...`
   - ✅ 正确：`FLMR（一种 2023 年提出的多模态细粒度检索方法，Lin 等, NeurIPS 2023）`

5. **专业术语首次出现时必须附通俗解释**
   - 括号内：`max-sim（每个 query token 找最相似的 document token）`
   - 脚注式：`「晚期交互」指 query 和 document 编码为多 token 后再计算相似度`
   - 比喻：`ReT 像一位会做笔记的阅读者`

**自检清单**（生成报告后必须全部勾选）：
- [ ] 报告中所有缩写首次出现时都有展开
- [ ] 报告中所有符号首次出现时都有定义
- [ ] 报告中所有指标首次出现时都有"是什么/为什么高/为什么低"的解释
- [ ] 报告中所有前人工作都有"一句话定位"
- [ ] 方法/架构图已嵌入"核心图速览"，每张嵌图都经过 Read 视觉核验（无截断、caption 匹配）；每张图的解读结论来自亲眼读图而非正文转述
- [ ] §1.4 思维链每一环都有证据标注（原文明述/据数据推断/重构-原文未交代），无推断冒充作者原话
- [ ] 报告中每个**关于其他论文**的事实断言都通过了 `cite_verify`（带核验出处标注），或已显式降级为【未核验——仅模型记忆】
- [ ] §4.10 后验影响已由 `paper_citations` 数据填写（或标注外部核验不可用）
- [ ] 基础知识地图已填；每数据集有卡片+样本（或明写给不出）；每基线有定位/公平性/缺席分析；§4.3 沉默对照清单逐条对账完毕
- [ ] §2.8 深入讲解（伪代码/复杂度/数值细节/边界）已完成；训练资源账本为交代值或带出处的区间估算
- [ ] 一个不熟悉该子领域的研究生读完后，能复述出方法的核心机制

> **违反这条原则 = 报告失败**。技术深度不等于术语堆砌——能用大白话讲清楚才是真功夫。

## ━━━ 📚 基础知识地图：读懂本文需要什么 ━━━

> 本节让读者**不必先去翻教科书**：把本文依赖的前置知识整理成一张最小地图——每个概念给"一句话定义 + 在本文中的具体用途 + 需要理解到什么深度"。总量控制在 5-8 个概念，按在论文中首次出现的顺序排列；超过 8 个说明抓错了重点，砍掉次要的。

| # | 概念 | 一句话定义 | 在本文哪里用到 | 需要懂多深 |
|---|------|-----------|---------------|-----------|
| 1 | [如"对比学习"] | [ELI5 级定义，禁用未解释的术语] | [§X 的 Eq.Y / 阶段 Z] | [只需知道 A 层面；不必理解 B] |
| 2 | [如"KL 散度"] | [...] | [...] | [...] |
| ... | ... | ... | ... | ... |

> **规则**：
> - 每个概念的定义本身也必须自过 ELI5 标准（定义里出现的术语要么解释过、要么在表中更靠前已定义）
> - "在本文哪里用到"必须精确到章节/公式/阶段编号——知识地图的价值在**接线**，不在罗列
> - "需要懂多深"是本节最有价值的列：告诉读者哪些可以安全跳过（如"本文用到 LoRA 的输出形式，不需要理解其低秩分解推导"）
> - 概念若涉及外部事实断言（"X 由谁在哪年提出"），同受 cite_verify 纪律约束

## ━━━ 1. 问题背景与分析 ━━━

### 1.1 研究问题 —— 作者发现了什么？

**一句话概括**：[这篇论文要解决什么问题？]

**问题溯源**

> 回答"作者发现了什么具体问题"。不要笼统地说"效果不好"，要具体到：在什么任务/场景/指标上、现有方法表现如何、出现了什么具体的 failure case。用论文中的具体证据来说明问题的严重性（如"现有方法 SOTA 在 X 场景下性能从 85% 骤降到 52%"），让读者感受到问题的真实性和紧迫性。

> **💡 核心洞察**：[用1-2句话提炼作者发现的关键洞察]

### 1.2 问题背景与重要性 —— 为什么这个问题重要？

[这个问题的现实/学术背景是什么？历史演进或发展阶段。]

**为什么这个问题重要？**

| 维度 | 影响 |
|------|------|
| 下游任务 | [对什么应用/系统有直接推动作用？] |
| 实际应用 | [在什么真实场景中有价值？] |
| 理论理解 | [对什么基础问题有新的认识？] |
| 不解决的代价 | [如果持续不解决，会对领域发展造成什么阻碍？] |
| 影响范围 | [仅影响一个子领域还是广泛影响多个方向？] |

### 1.3 现有方法的不足 —— 前人为什么没能解决？

> 前人是如何尝试解决这个问题的？本节用叙述性段落逐一分析**每个主要相关工作的根本局限**，避免笼统总结"效果不好"。

**根因分析** —— 不要停留在"效果不好"的表面描述，深入分析根本原因。**核心瓶颈用 🔴 标记，次要瓶颈用 🟡 标记**。对每个瓶颈说明三层：① 名称（一句话定义）② 什么假设 / 设计导致了它 ③ 在什么场景下会暴露。

**🔴 瓶颈 1：[名称，如"架构假设的局限"]**
[具体说明：什么假设？如何限制？典型场景下表现如何？]

**🔴 瓶颈 2：[名称]**
[具体说明：...]

**🔴 瓶颈 3：[名称]**
[具体说明：...]

**🟡 瓶颈 4：[名称]**
[具体说明：...]

**🟡 瓶颈 5：[名称]**
[具体说明：...]

**作者是如何发现这些不足的？**

作者通过什么观察、实验（如诊断实验、可视化分析、failure case 分析）或理论分析发现了现有方法的根本缺陷？描述作者的发现过程。建议写成 1-2 段连贯叙述。每个关键环节按 §1.4 内「思维链证据规则」块注明出处；原文未交代发现路径时，直接写"论文未说明其发现过程，仅以『我们发现…』一笔带过"——**禁止**编造一个合理化的发现故事填空。

### 1.4 作者的分析思路与突破口

> 作者解决这个问题的核心思路是什么？这个思路和前人思路的本质区别在哪里？

**从观察到方法的思维链条**：

```
  诊断性观察               关键 insight              方法转化
  ───────────              ──────────               ────────
  [作者做了什么观察/      →  [揭示了什么关键      →  [如何将insight转化
   预实验？]                  insight？]               为可操作的方法设计？]
  [出处标注]                [出处标注]                [出处标注]
```

**核心思路一句话**：[用一句话概括作者的解决方案思路。这一句构成从第 1 节到第 2 节的桥梁。]

> ### ⚠️ 思维链证据规则（硬性）
>
> 学术写作几乎都是**事后重构的叙事**（hindsight）——真实的发现常混杂偶然与弯路，但论文会把故事打磨成必然。为防"把故事当史实"和"无证据时编故事填空"，思维链的每一环必须标注出处，三选一：
>
> | 标记 | 含义 | 示例 |
> |------|------|------|
> | `[原文 §X 明述]` | 论文确实交代了这一步 | "作者在做 X 探针实验后发现……（§3.1）" |
> | `[据 [表格/图/公式] 推断]` | 从论文数据合理反推，作者未明说 | "消融表 2 显示去掉 A 后仅降 0.3，**推测**动机是……" |
> | `[重构——原文未交代]` | 论文没写，这是叙述性重构 | "论文仅以『我们发现』带过；此处为基于方法结构的合理重构" |
>
> **没有证据支撑的环节宁可留白**（直接写"论文未说明发现路径"），禁止用想象把链条抹平。读者必须能分辨"作者说过的"和"报告替他猜的"。

> **写作要求**：以上 1.1-1.4 的分析应写成连贯的叙述，而不是孤立的问答列表。读者应能自然跟随"问题发现 → 根因分析 → 突破口寻找 → 核心思路形成"的完整逻辑链。避免重复叙述论文内容，重在分析作者的思考过程——但每一次"分析思考过程"都受上面的证据规则约束。

## ━━━ 2. 方法详解 ━━━

> **组织原则**：先让读者理解方法"是什么"（2.1 直觉 → 2.2 全景），再追问"从哪来、为什么这样设计"（2.3 溯源），最后深入细节（2.4-2.7）。读者在看到"本文从哪个基座改了什么"之前，应已经对方法本身有了基本认知。

### 2.1 核心直觉

> 用通俗的语言解释方法的核心思想——像向非专业人士解释一样。这是读者建立心理模型的入口。

**一句话直觉**：[用一句话讲清楚：方法的核心 trick 是什么？]

**类比**：[用一个生活化或跨领域的类比帮助理解。如："就像一个翻译，先把中文翻成英文，再查英文词典，最后翻回中文——虽然绕了路，但英文词典的资源更丰富。"]

### 2.2 方法全流程概览

按执行顺序完整叙述方法的全部流程（输入 → 各阶段/组件 → 输出），让读者获得方法的"森林视图"。

**写作要求**：
- ▸ **叙述性语言**：用连贯的段落讲述方法的完整故事，避免孤立的 bullet points
- ▸ **覆盖所有主要组件/阶段**：不只是作者强调的亮点，而是端到端的全部流程
- ▸ **执行顺序**：从输入开始，按数据实际流动顺序逐步推进，到最终输出结束
- ▸ **读者友好**：面向有通用 ML 知识但不熟悉该领域的读者，兼顾专业性和可读性
- ▸ **可追溯**：标注论文中的图表/算法编号（如"如 Figure 2 所示"、"见 Algorithm 1"）
- ▸ **结合图讲**：叙述到各阶段时点名"核心图速览"图 A 中的对应区块（如"这一步就是图 A 里左侧的 Encoder 堆叠"），让读者的文字路径与图像心理模型对齐
- ▸ **关联公式**：在每个阶段末尾标注对应的关键公式编号（如"→ 详见公式 3"），让读者知道该阶段的核心数学在 2.6 中的哪个公式展开
- ▸ **提及但不展开公式**：文中可引用公式编号，但不展开公式细节（留待 2.6 节）
- ▸ **目标长度**：3-6 个叙述性段落

**数据流总览表**（附于叙述后）—— 此表只描述**阶段名和操作类型**，**不列张量形状**（形状在 §2.4 详述）：

| 阶段 | 输入（形式） | 核心操作 | 关键公式 | 输出（形式） |
|------|-------------|---------|---------|------------|
| ① [阶段名] | [数据模态/类型] | [一句话核心操作] | Eq. (X) | [数据模态/类型] |
| ② [阶段名] | ... | ... | Eq. (Y) | ... |
| ... | ... | ... | ... | ... |

> **为什么 §2.2 不写张量形状**：读者此时还不熟悉本方法的符号系统（$B$、$L$、$D$ 各代表什么），形状信息是噪声。详细形状在 §2.4 配合「张量符号约定」一起呈现。

### 2.3 方法溯源分析

> ⚠️ 读者此前已通过 2.1 和 2.2 理解了方法"是什么"和"怎么做"，本节回答"从哪来"和"为什么这样设计"。

**原创性判断**：[本方法是否为原创？如果是基于前人工作改进的，原创性体现在哪里？如果是原创，原创性体现在哪里。]

**基座方法速览**（⚠️ 每个基座的"提供了什么"都是关于**其他论文**的事实断言——写入前必须 `cite_verify` 核验，在表末列附核验出处；未通过的降级标【未核验——仅模型记忆】）：

| # | 基座 | 提供了什么 | 本文的改变 | 外部核验 |
|---|------|-----------|-----------|---------|
| A | **[方法名]** ([作者] [年份]) | [核心设计/范式] | [关键改动] | ✅ [venue, year, 被引 N] / ⚠️未核验 |
| B | **[方法名]** ([作者] [年份]) | [核心设计/范式] | [关键改动] | ... |
| C | **[方法名]** ([作者] [年份]) | [核心设计/范式] | [关键改动] | ... |
